# 普通员工使用说明

## 准备三项输入

1. 上传本系统订单列表，支持 CSV、XLSX 或 XLSM。
2. 填写订单币种，例如 `COP`、`MXN` 或 `BRL`；系统不会默认币种。
3. 填写订单开始日期和结束日期，两个日期都包含在对账范围内。

示例请求：

> 这是我们系统 2026 年 9 月 12 日至 9 月 14 日的 COP 成功订单，请使用 tdaypay-merchant-reconciliation 对账。

Skill 会核对代收和代付成功订单，查询 TDayPay 订单与 `UNPAYOUT_AMT + ORDER_AMT` 记账流水，并在每笔订单创建日期至第三个自然日之间查找对应流水。

## 查看六个输出文件

| 文件 | 用途 |
| --- | --- |
| 对账总结 | 查看双方订单数、金额、差异、未结算和流水覆盖结果 |
| 差异订单 | 分别查看“我方有、TDayPay 无”和“TDayPay 有、我方无” |
| 未结算订单 | 区分明确未结算与结算状态待核实 |
| TDayPay 成功订单 | 保留指定期间内的平台成功订单明细 |
| 未查到流水订单 | 区分确认缺少流水与三日观察期尚未结束 |
| TDayPay 记账流水 | 查看全部指定口径流水、成功订单关联流水和订单号匹配但超窗流水 |

所有非空单元格均保存为文本，长订单号不会转成科学计数法。

## 结果解释

- “差异订单”表示同一完整平台订单号只出现在一方。
- “字段差异”表示平台订单号相同，但商户订单号、金额、币种或支付类型不一致。
- “明确未结算”仅指 TDayPay 结算状态为 `UNCHECK`；空白或未知值单独列出。
- 订单创建当天没有流水时，会继续查询其后三个自然日。第三日出现的流水有效，第四日出现的流水只作为超窗证据。
- 三日窗口尚未结束的订单显示在“观察期未结束”，不会提前判定为缺少流水。

## 依赖与权限

- 需要已认证的 TDayPay 商户 MCP，具备当前商户的币种查询、订单导出和记账流水导出权限。
- 需要工作区文件读取和输出目录写入权限，以及 Python、Node.js 和表格运行时。
- Skill 只使用当前已认证商户与用户指定范围，不申请扩大数据权限。

## 常见失败

- 缺少文件、币种或日期：补齐输入后重新运行。
- 币种不受当前商户支持：核对币种，不能用其他币种替代。
- 文件列名缺失或重复平台订单号：按报错修正源文件；Skill 不会把不完整证据当作零差异。
- 导出任务失败、下载过期或行数不符：重新导出受影响日期或流水分段，再进行对账。
- 当天或最近三日订单仍在观察期：待窗口结束后重新运行，确认是否真正缺少流水。

## 安全与归档

原始导出和明细工作簿应保存在受控目录，并按公司权限规则共享。对外展示或竞赛材料使用脱敏运行证据，只保留日期、币种、计数、校验结果和导出任务数量，不展示完整订单号、联系方式、账户信息、凭证、任务 ID 或临时下载链接。
